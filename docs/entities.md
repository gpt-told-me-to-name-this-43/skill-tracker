# Документация сущностей и MVP сценарий

## Основные сущности

### 1. User (Пользователь)
Пользователь системы.
- **Особенности:** Регистрация требует `email` и `username`. Email нормализуется (приводится к единому регистру) при регистрации и логине. `hashed_password` никогда не отдается в ответах API.

### 2. Skill (Навык)
Справочник доступных навыков (например, Backend, QA).
- **Особенности:** Названия уникальны. Запрещено создавать дубликаты даже в другом регистре букв.

### 3. UserSkill (Навыки пользователя)
Связь конкретного пользователя и навыка.
- **Важно:** Таблица хранит только `experience` (абсолютное значение XP). Колонки `level` в модели БД **НЕТ**. Уровни и прогресс до следующего уровня (`current_level_xp`, `next_level_xp`, `progress_to_next_level`) вычисляются API на лету.

### 4. Task (Задача)
Сущность задачи.
- **Особенности:** Поле `creator_id` проставляется автоматически из текущего авторизованного пользователя. Поле `status` не может быть изменено через общий `PATCH /tasks/{id}`, для этого существует строгий эндпоинт `/tasks/{id}/status`.

### 5. TaskSkill (Награды за задачу)
Связь задачи и навыков. Указывает, какой опыт получит исполнитель при завершении задачи.
- **Особенности:** Награды задаются списком. Полностью перезаписываются через `PUT /tasks/{id}/skills`. Запрещены дубли скиллов и награды `exp_reward` равные 0 или превышающие 1000.

### 6. ExperienceLog (История опыта)
Журнал начислений. Фиксирует, сколько XP, по какому навыку и за какую задачу получил пользователь. Служит историей транзакций опыта.

## Главный сквозной сценарий MVP
1. Создать пользователя (и пройти нормализацию email при логине).
2. Залогиниться и получить `access_token`.
3. Создать или выбрать существующий `Skill`.
4. Создать задачу (`Task`).
5. Назначить исполнителя на задачу через `/tasks/{id}/assign`.
6. Задать награды задачи через `PUT /tasks/{id}/skills`.
7. Перевести задачу в статус `done`.
8. Проверить, что XP исполнителя вырос в профиле.
9. Проверить, что `ExperienceLog` пополнился записью.
10. (Если фронтенд готов) Пройти весь путь через UI, убедившись, что progress bar отображается корректно.
